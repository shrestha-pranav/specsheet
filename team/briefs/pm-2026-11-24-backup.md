the NVMe root fs (86% full). No backup exists. Losing raw/ loses evidence that delisted pages can never re-supply.

## Part 1 (now, no accounts)
- Second physical disk: /mnt/hdd-3tb (NTFS, spins down, has a dirty-NTFS auto-repair history). BEFORE touching it:
  `kb show host-storage`, `kb impact host-storage`, `kb show 2026-08-07-hdd-power-loss-resilience`; follow them.
- Script `scripts/backup.sh` (new; in-project): (1) `sqlite3 state/specsheet.sqlite ".backup <tmp>"` then copy;
  (2) `rsync -a --ignore-existing` for raw/**/blobs (immutable) and plain `rsync -a` for snapshots.jsonl/index files;
  never `--delete` (retention deletes come only from the source-policy retention job, applied to the copy too);
  (3) assert mountpoint (`mountpoint -q /mnt/hdd-3tb`) else exit non-zero; never write into an unmounted dir.
  Target dir: /mnt/hdd-3tb/backups/specsheet/ (confirm against host-storage note).
- Schedule: systemd user timer `specsheet-backup.timer` 04:15 nightly (unit files live in the project dir, symlinked).
  Healthchecks-style failure signal: follow the vault `obs-alerting` note (no new push channel; morning digest rule).
- Verify: a restore drill (copy one source back to /tmp, sha256 blobs match their names). Record in report.
