## ID-length fix (A3-impl note)
Cause: long strings used as mfr_model. Fixed in parse():
- Energy Star: comma lists in one cell ("BE24E, BE24EQSB, BE24EQSB-P, ...") -> first token = model, rest = model_variant aliases;
  wildcard families ("S24A40*###  (*=0-9, ...)") -> key = text before first space, full text alias kind model_pattern, fingerprints.wildcard_pattern.
- DisplayHDR: model = last model-like token; fallback slug <= 32 chars (was whole-cell slug, e.g. HP-Elite-Dragonfly-G2-Notebook-PC).
- ASUS: pages without a Model row took the URL slug (PROART-DISPLAY-PA278QV-GEN2-PA278QV2); now a model-like title token, else slug <= 32.
After re-parse: 0 mfr_model/mfr_sku values > 32 chars in all five stores (Lenovo product keys max 31).

   Table includes laptops/OLED notebooks; model_token handles them; category resolution is the matcher's job. Brand token for LG is LGE.
4. Cross-link rules + verified examples + measured overlaps are in research/monitors/identity.md (new section). Key rule: stem() = cut at / or #,
   drop one trailing -X market suffix, strip non-alphanumerics; stem match = candidate, exact normalised from two maker/regulatory sources = verified.
   Overlaps: DH-LGE vs LG US 4 exact + 74 stem; ES-ASUS vs ASUS US 108 exact + 9 stem; DH-ASUS vs ASUS US 86 exact; ES-LG vs LG US 0 exact, 26 stem.
