# A1 r11: major-appliances profile + PDO ruling (2026-11-26)
Files: research/refrigerators/spec-profile.yaml (29 keys), research/dishwashers/spec-profile.yaml (20 keys); both validate against schemas/category-profile.schema.json (0 errors). No code/data edits. ES facts below are live Socrata counts 2026-11-26, crawler UA, ~1 req/s.
**1. Scope: one category per appliance type** (refrigerators, dishwashers, then clothes-washers, clothes-dryers, freezers; room-acs/dehumidifiers/cooking later), not `appliances`+subtype. Registry SOURCES maps a source to exactly one category, and presets, the D8 gate, schema and the grid are per category. The types share almost no comparison keys. One parameterised energystar_appliances adapter can still serve all of them (one SOURCES entry per dataset id).
**2. Profiles: key findings that change the plan:**
- ENERGY STAR (ES) has no fridge depth, no dishwasher height and no noise in any dataset, so those keys can only come from maker pages. ES has no french-door type ("Bottom Freezer" covers it), so config.style is maker-only.
- Wildcard rows: 1,647 of 4,942 fridges (33%) and 370 of 753 dishwashers (49%). Skipping them, as the TV and purifier importers do, would drop a third to a half of each category. Ruling: a pattern row is a published row (scheme x_energystar_model_pattern, flag gen.is_pattern) = one DOE basic model. It MAY assert, for each concrete SKU it covers, only the energy-defining facts: ES status, Most Efficient, date, kWh, DOE volumes, place settings, water, product class/type, refrigerant, drying/soil. It MAY NOT assert: finish, hinge, trim, any dimension, UPC, connectivity, noise, price or features.
  - Matching: ES does not document what `*` means for appliances (the TV filings did), so a concrete SKU links only through additional_model_information, or through a whole-string match with `*`=1 alphanumeric, `#`=1 digit, `R/L`=R or L, where exactly one pattern row matches. That link is a covered_by_certification edge, never a merge and never an expansion.
- DOE test procedures are a condition: fridge Appendix A vs pre-2014 A1 (adjusted-volume factor changed); dishwasher C1 vs C2. Washer J2 vs the new J and dryer D1/D2 apply to the later washer and dryer profiles (not written yet). Adjusted volume is larger than physical volume (Absocold total 4.8 / adjusted 5.8), so it is never used as capacity. Model-number digits (Samsung RF29) are a size class, not capacity. Washer "IEC cu ft" is larger than DOE cu ft (later profile).
- ES data traps: 38 Beko dishwashers have width 59.8 (centimetres typed into the inches column) and are quarantined, not converted. `better_than_us_federal_*` is a percent despite the _kwh name. Refrigerant is free text mixing charge and GWP, and is blank on 68% of rows. Fridge product-class "3" means two different things (a top-mount fridge and a compact cooler). There are duplicate pd_id filings (Bosch DWHD640EFP twice). Absent from ES = unknown, never false.
**3. Presets** (scope.sources [regulatory, manufacturer] as for purifiers; populations are ES US rows; ES fills every gate key, so fill should be >=0.95):
- P1 counter-depth fridge: by counter_depth=true, compact=false (477 rows / 46 brands). Gate: width<=36.25 in, capacity.total_ft3>=20, kWh<=600, cert.energy_star; 58 rows / 15 brands match. Use TOTAL volume: the survey's adjusted-volume version overcounts (261 rows).
- P2 24 in dishwasher: by type=standard, width 23-24.25 (549 / 70). Gate: >=14 place settings, <=3.5 gal/cycle, kWh; 362 / 53 match. noise.dba is shown as a column but is NOT a gate key: Bosch is the only dBA source we can reach, so it fails min_brands=2. A "<=44 dBA" preset waits for a second dBA maker.
- P3 (phase 2, clothes-dryers) ventless heat-pump >=4 cu ft: by ventless (99 / 29), 60 / 12 match. Voltage is not gated (blank on 89% of ES rows).
- P4 (phase 2, clothes-washers) front-load >=4.5 DOE ft3 with IWF<=3.2: 157 / 15.
**4. Ruling (A2-pb r10b): NO.** A regulatory leaflet's per-port Output list is a rated-output (fixed PDO) list, not a complete PDO enumeration, so pd.pps false must not be written for any of the 10 rows. This is the same result as A1 ruling 1: a fixed-PDO-only list never yields a negative. PPS is an augmented PDO (APDO), and these listings routinely omit it. None of the 10 texts names PD, PPS or any APDO, and their 5/9/12/15 V rows are consistent with a PPS-capable source.
- Criteria for when a document does count (all must hold): the maker's own document for that exact SKU; every output port named; the list is a protocol list, or is labelled as the full source capabilities / PDO set, or the same document prints an APDO/PPS row for some port (that shows it enumerates APDOs); the text is checked by eye (not a multi-column text layer); claim basis=complete_enumeration with the list kept raw.
- The list may fill pd.max_fixed_voltage (12 V BBA010/BPD011, 15 V BBA018/BPD022, 9 V BPD015/007/008, 5 V BPD006/BPD004) with basis=rated_output (a new basis value: A3 must add it to the power-banks conditions enum first, along with a policy). It does not bound out.max_single_port_w (never VxA).
