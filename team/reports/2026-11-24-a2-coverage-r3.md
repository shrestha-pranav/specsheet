## What was built (one polite GET per page, crawler UA, robots respected; recorded in merchants.md)
1. **Ubiquiti** `ubiquiti_routers@1` (techspecs.ui.com, 53 gateways and APs). Per-band streams, rates and BW come from the band's own rows. RAM, cores/GHz, PoE in/out text, ports, VPN and coverage are captured. The pages never name the SoC, only the CPU core ("Cortex-A53"), so `hw.soc_*` stays unknown for Ubiquiti. LAN count = Port Layout total minus the default WAN ports (console and MGMT ports excluded).
2. **BenQ** `benq_monitors@1` (136 spec pages, 134 parsed). `flk.pwm=none` is written only from an affirmative "Yes", and the quote is kept. PD wattage is taken only when exactly one upstream figure is stated ("35W / 96W" writes nothing). **Dell** was skipped: the specs load client-side and the sitemap lists no monitor URLs.
3. **GL.iNet** `glinet_routers@1`. Of 45 router pages, 35 have a Specifications table. The comparison tables on the same pages are never read. **eero** was skipped: its pages show no maker model number and only aggregate speed and coverage.
4. **Kingston** `kingston_ssd@2`. A `legacy_blocks()` parser was added for the two-column layout. Output for the six current datasheets is unchanged. NV2 and NV1 print NAND "3D" and no DRAM row, so those stay unknown.
5. **Bare DRAM-less** `_ssdprose`: it now maps to the new profile value `hw.dram_type: dramless`; HMB is left unknown. One narrow exception to the hedge filter: "this DRAM-less drive ..." is read even when the sentence also compares something else. `sandisk_ssd@4` and `teamgroup_ssd@4` are version bumps only. Claim diff against a HEAD worktree: SanDisk +22, 0 removed; TEAMGROUP 0; Kingston +132, 0 removed.

## Open

- The SoC demand question (Q9) is now partly answered by GL.iNet only. TP-Link, NETGEAR, ASUS and Ubiquiti need FCC or OpenWrt cross-checks.
