## 1. Package minting (importer side, no adapter change)
- Turned on per category with `features: [bundle_packages]` in research/<cat>/category.yaml. Robovac also sets `bundles.pack_words: [Complete]`.
- Inputs: `fingerprints.packages` {sku, title}, and mfr_sku identifiers whose `option` names the model plus an add-on.
- A package has key mfr_sku (level package), no claims, parent or family, so it inherits nothing.
  - `contains` -> each member model (method `bundle:<source>`, incl. a second model named in the title); `contents` [{entity|description, qty}].
- **Shape for A4:**
  - The model detail gets `bundles: [{id, name, sku, qty (units of THIS model), contents}]`; render it as "Sold as bundles".
  - The package detail products/<id>.json: kind=package, `specs: {}`, `contents`, the `contains` relation. Packages are not index rows and not in lookup.
  - Both fields were added to schemas/public-detail.schema.json.

## 2. Basis in the index (v1_publish row_of)
- **Shape for A4:** `row.x[fieldKey].basis = {claim_basis?: <enum>, power_mode?: <enum>}`, the same object as the detail's `specs[k].basis`; the shell's toRow spread already picks it up.

  - `mfr_unstated` / `unstated` are omitted: absent means that default, exactly as METHOD_DEFAULTS already does.
