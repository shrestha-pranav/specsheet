## What changed
- **Certification-only rule (generic).** The profile gets `index_rows: {substantive_keys, certification_keys}`. `catmeta.substantive_keys` requires the two lists to partition the spec keys exactly, so a new key fails loudly. For air purifiers the certification keys are CARB certified/type/date/EO, eff.energy_star, eff.most_efficient and cert.maker_listed. v1_publish: an entity whose trusted values with `has_value` are all certification keys goes into the compact shard instead of the default rows. Lookup, detail and v0 compat behave as before. Facets and `count` cover default rows only.
- **For A4, the shape:** `categories[].certification_only` (also in the manifest) = `{index: ["<cat>/index-certonly.json"], count, certification_keys, rule}`. Each row is `{id, kind, brand, brand_id, name, ids, search, v, lifecycle, scope: "certification_only"}`, with no `s`, completeness or `x`. The detail gets `index_scope: "certification_only"`. Preview rows of such entities carry `in_trusted: true, certonly: true`. app.js currently treats a preview row with no trusted base as unreviewed, so the preview merge must also load or recognise the certonly shard. Details may also carry `same_hardware[]` (role declared_alias/certified_base, record, declaration, date, method, status, transferred).
- **scripts/xwalk.py (new, transform xwalk@1, pinned like tvcert).** Feature `model_crosswalks` reads `data/decisions/<file>`. A reviewed pair needs: a human by and at; one quote naming both exact strings; both entities existing and distinct; one stated market; no contradicting partner; no disagreement on `compare_keys`. It then yields `same_model` with no merge and no transfer. Feature `same_hardware_relations` handles a declared ES alias that is another entity's key: `same_hardware_as` alias -> base. The method is `es-declared:exact` only if the raw clause re-checks as affirmative (no only-difference, identical-in-performance, derivative or negation), the record states US, the record is dated, there is one base and nothing disagrees. Otherwise it is not-exact, market, undated, several-bases or conflict (proposals; a conflict also lands in identity_conflicts). Over an approved edge only `transfer_keys` move, and they must be profile certification keys. They use their own extractor `energystar_airpurifiers_same_hardware@1`. model_variant aliases get no edge.
