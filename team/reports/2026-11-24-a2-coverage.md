## Laptops trace (one MTM, e.g. 21K7005FUS): raw -> parser -> mapping -> claim -> policy -> published
- raw: the PSREF bundle has the Display / Memory / Memory Slots cells for every MTM. **Not dropped there.**
- parser (lenovo_psref@2 COLMAP): writes each cell once under ONE key (Display -> disp.size, Memory -> mem.size, Memory Slots -> mem.slots).
- mapping (import.py load_psref): columns with several maps_to targets go to `multi` and were only counted as
  `psref_column_multi_target_needs_parser`. **The drop happens here**: no stage ever split these cells.
- normalise/policy: the Memory Slots literal ("Two DDR5 SODIMM slots ...") cannot normalise to an object, and mem.slots was not in
  claim/mfr-structured-datasheet@2, so the claim stayed a candidate.
- Fix: `import.py+psref-split@1`. crawler/adapters/_lcell.py is a pure parser, wired into import.py the same way as cpu-split. Policy
  claim/psref-split@1 has explicit keys and the _lcell fingerprint pinned (approved by the coordinator). A split claim is accepted only if
  its parent is accepted, or the parent is a candidate with no human decision (the Memory Slots case). A rejected parent blocks it.

## Monitors (4,133 rows)
- flk.pwm 0% -> 21.1% (872): ASUS 320/631, LG 406/737, Lenovo 146/669. All three makers print an explicit flicker-free statement that the
  adapters left unmapped. Now research/monitors/label-mapping.yaml stores it as flk.pwm = none, an official maker declaration with the literal
  quoted. "No" or silence writes nothing. Policy claim/monitor-flicker-label-map@1. Adapters are untouched, so no parser pins changed.
  The >= 50% target needs Dell/BenQ/MSI adapters, which is P1 brand work.
- usb.usbc_pd_w 4.6% -> 4.9% (ASUS 91 -> 105, via the "USB-C Power Delivery" row). **Still dropped:** Lenovo PSREF "up to 90W PD"
  (~60 models). lenovo_monitors@1 only matches PD before the number. Fixing it needs an adapter edit, which means re-issuing claim/mfr-monitor-structured@2
  AND rel/source-stated-hierarchy@2 (both pin lenovo_monitors@1). Not done; this is for the coordinator.

## Other zero-fill gaps: source vs us
- TV dimming zones: TCL prints "Up to 2100+ zones" (a family ceiling, correctly not normalised; A1's hdr.dimming_zones_max_claim). Others do not publish zone counts. **Source.**
- SSD controller/NAND/HMB: Samsung only in spec tables. SanDisk/Teamgroup name NAND type and controller in prose only ("BiCS8 QLC", "IG5666
  from InnoGrit"). **Partly us**: needs sandisk_ssd/teamgroup_ssd edits, and those parsers are pinned in rel/source-stated-hierarchy@2. Not done.
- Router SoC: Broadcom/Qualcomm/MediaTek appear on 6 of 248 maker pages; ASUS gives only "2.0 GHz quad-core" (hw.cpu_cores is filled). **Source.**
- Power banks (left to the chargers agent, _powerbank.py untouched): pd.pps 14.9%, cap.energy_wh 16.1%. "PPS"/"Wh" strings appear on all 22 Anker
  and 37 Belkin pages, but the samples I checked were site chrome (nav filters). This needs a per-adapter check by the chargers agent before calling it a drop.
  Cuktech/Sharge write "88Wh/90Wh 3.6V" and "18Wh;17.64Wh" (typical/rated pairs), which stay candidates: a rated-vs-typical rule is needed in _powerbank.py.
