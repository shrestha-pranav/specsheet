# specsheet api-worker

Cloudflare Worker `specsheet-api` on `<sub>.workers.dev`: the API, MCP and metrics in front of the free dataset (product/decisions.md
D2, D3.4 to D3.7, D4). The site and static dataset stay on GitHub Pages. **L1 = free preview: `PAYMENTS=off`.** No 402 anywhere, no
facilitator call, payment headers ignored. The paid code path (x402) exists for L2 and ships disabled. Nothing here is deployed.

## Modes (`wrangler.jsonc` vars)
- `PAYMENTS` = `off` (committed default) | `on` (L2 only: needs the `PAY_TO` secret and a valid x402 config; an invalid config fails closed with 503).
- `PREVIEW` = `on` | `off`. `off` is the kill switch: every data route answers 503 `preview_paused`, and `/`, `/health` and discovery stay up.
- `BREAKER_DAILY` (default 60000): the global data-route requests per UTC day before 503 `preview_capacity`.
- `SITE_ORIGIN`: the only CORS origin for the `/v1/miss` and `/v1/event` beacons.
- Prices: `PRICES` in `src/config.ts` (`query`, `match`, `changes`, `bulk_category`, `bulk_all`), provisional (D3.3). They show only when `PAYMENTS=on`.

Query: `GET /v1/query?category=laptops&filters=cpu.cores>=8,mem.size>=16&fields=cpu.model,mem.size&limit=10`. The ops are `>= <= > < != = ~`, and
only known values match. Each result has `specs[key] = {value, unit, kind, sources: [source id]}` plus a `sources` list for those ids.
Match (`/v1/match?title=`, MCP `match_product`) is a TS port of `scripts/match.py`. `test/match-parity.test.ts` checks that it returns the
same ids, basis and confidence on every fixture title. It is live because parity passes. If the pack has no `match/catalogue.json`, it
returns 404 `not_available` and disappears from discovery.

## Bounds, quota, breaker (D3.6, D3.7)
- Bounds are checked before any data load (`src/bounds.ts`). Unknown or repeated parameters get 400. Invalid requests are never charged, but each counts once against the quota.
- Client key: IPv4 /32 or IPv6 /64 from `CF-Connecting-IP`. Users behind one NAT share a budget (llms.txt says so).
- Layer 1 is the Rate Limiting binding (60/min). Layer 2 is the `Budget` DO (SQLite), 16 shards. Counts live in memory and are written
  at most every 60 s, with an alarm as backstop. The daily budget is 1000, shared by REST and MCP tool calls (a batch of N costs N, and
  internal dispatch is not re-counted). Beacon budgets: miss 30/day, event 200/day. A 429 carries `Retry-After` = seconds to 00:00 UTC.
- If a DO fails, the request falls back to the binding only and writes an `ops`/`quota_degraded` point. Paid routes fail closed instead.
- `Breaker` DO: shards sync their data-route deltas at most every 30 s, or sooner as they near the threshold. A tripped breaker is cached
  30 s per isolate (at no DO cost). It also holds the daily salt: 32 random bytes, created on first use and deleted at 01:00 UTC the next day by alarm.
- Cache: the key is release + route + sorted validated params. 200s and 404 `not_found` are kept 300 s in a per-isolate LRU and in `caches.default`.
  Cloudflare documents working cache operations on custom domains and treats workers.dev as a normal cache target. Cache hits still count against the quota.

## Metrics (D4, measurement-plan §1-2)
`src/metrics.ts` writes one Analytics Engine point per request (MCP: one per logical tool call) to `specsheet_requests`, with the fields in
contract order. `cid` = HMAC(daily salt, client key | UA family), first 16 hex. These are never written: IP, full UA, request bodies,
filter values. Miss text is lowercased, has emails, URLs and phone-like runs replaced by `·`, and is cut to 80 chars before writing.
`X-Specsheet-Test: 1` marks a request as `test`. AE keeps points for three months (Cloudflare AE limits page), and they cannot be deleted. Weekly KPIs: `scripts/kpi.sh` runs `scripts/kpi.sql` and writes
`../state/metrics/<week>.csv`. The token is materialized once with `scripts/kpi.sh --materialize` from `pass specsheet/cf-analytics-read`
(chmod 600).

## Local development (no accounts)
```
cd api-worker && npm install
npm run pack        # = python3 -I ../scripts/build_r2.py --tier free --shard-hex 3  -> pack/ (gitignored; gate: data/source-policy.yaml)
npm run dev         # http://localhost:8787
npm run typecheck && npm test   # units, match parity, route matrix in all 5 modes on wrangler dev, no-PII, x402 flow (mock facilitator)
npm run load-test   # workerd process CPU + wall, then Worker-only CPU in Node V8 (scripts/cpu-bench.mjs)
npm run route-table # regenerate the table above after editing test/route-matrix.json
```
The pack must be built from a docs tree that used the same source policy. If it wasn't, `build_r2.py` refuses: run `scripts/build.py` first.

## Owner deploy steps
### L1 free preview (launch checklist step 15)
Prerequisites: the pack is built for the release on Pages, so `/health` reports the same release and `policy_version` (`npm run pack` after
any new release), `npm test` is green, and `SITE_ORIGIN`/`STATIC_ORIGIN` in `wrangler.jsonc` are the real Pages URLs. No R2, no secrets
and no zone are needed at L1. Durable Objects (SQLite, Free plan), the rate limiter and the Analytics Engine dataset are created by the deploy.
```
cd api-worker && npx wrangler login && npx wrangler deploy
```
(`PAYMENTS=off`, `PREVIEW=on` as committed.) Then set `docs/site.json` `api_origin` to the printed workers.dev URL and republish Pages.
After that: `node scripts/route-matrix.mjs https://specsheet-api.<sub>.workers.dev` (checklist step 16). Also add Cloudflare usage
notifications at 50% and 80% of Workers and DO daily allowances. Kill switch: set `PREVIEW` to `"off"` and run `npx wrangler deploy`.
Rollback: `npx wrangler rollback`.

### L2 paid tier: after legal review only (not part of L1)
1. Settlement path, real fees and minimums decided (D3.3 L2 gate). `PRICES` updated. Paid content cleared at the sources (paid packs today hold ENERGY STAR only).
2. Build the paid pack (`python3 -I ../scripts/build_r2.py --tier paid --shard-hex 3 --out pack`), so this Worker version serves the paid tier.
3. Testnet first: `npx wrangler secret put PAY_TO` (a testnet address), set `PAYMENTS` to `"on"`, deploy, run `scripts/pay-test.mjs` against workers.dev.
4. Mainnet: CDP facilitator auth (TODO in `src/x402.ts`), `X402_NETWORK=eip155:8453`, `ALLOW_MAINNET=true`, `FACILITATOR_URL`. Make one small real purchase first.
5. Before any paid use, move the shell and data under the purchased domain (D2 deferred migration).
Secrets live only in `wrangler secret` and `.dev.vars`. Never commit them.
