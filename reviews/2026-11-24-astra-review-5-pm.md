# Astra PM review — 2026-11-24
Scope: nine requested repository files only; external primary documentation checked for licensing/platform claims. No implementation inspection or changes.
Fixed constraint: launch free; paid functionality built but disabled until the owner's legal review. Findings below do not reopen that decision.

1. **P0 — Make publication permissions explicit before applying ODbL to the free release.**
- D1.3 says one gate; the licensing audit still leaves free GH Pages unchanged; the release brief defaults unknown domains to free `facts_link_only`. A shared file with permissive defaults does not resolve this conflict.
- The audit has blocked Lenovo terms, unclear CSA/VESA reuse, provisional CARB permission and unaudited makers. Facts-only and robots compliance do not establish permission under upstream contracts/database rights; free distribution does not cure those gaps. Record uncertain sources as withheld pending an explicit disposition.
- EPA hosting does not establish that every manufacturer-contributed value is a federal government work; CARB public-record status likewise does not establish unrestricted reuse. Replace blanket public-domain assertions with source-specific evidence and attribution rules.
- Apache-2.0 code, CC BY documentation and ODbL compilation rights can coexist; define their file/output boundaries and preserve dependency notices. “Whole repo Apache” currently obscures those exceptions.
- ODbL already allows commercial use/resale. A future paid license can waive only rights specsheet controls; contributor rights and upstream restrictions must support that alternative grant. Sell service convenience independently of that unresolved grant. [ODbL §§2–4](https://opendatacommons.org/licenses/odbl/1-0/)
- “Produced works only need attribution” is incomplete: public use of a produced work from a derivative database can trigger the database/access obligations (§§4.4, 4.6). ODbL is not a ban on competitors selling copies. [ODbL](https://opendatacommons.org/licenses/odbl/1-0/)
- **Exit:** one versioned policy, explicit free/paid decisions and evidence for every published domain; unknown domains withheld; build fixtures prove excluded-only values cannot leak through records, indexes, facets, diffs or bulk. Mixed-source fixtures retain only independently supported values and permissible provenance. Publish post-gate category coverage and accurate license/attribution notices; document rights needed for any future waiver.

2. **P0 — Deliver a bounded, observable free preview and reconcile its contract.**
- README/config still use `PAID_ENABLED`, disabled routes returning 503, old prices ($0.001/$0.002/$0.002/$0.05), and a match stub returning 501. Decisions/brief instead require `PAYMENTS=off`, free query/match/changes and bulk 404. These files demonstrate specification drift, not completed preview functionality.
- Checklist step 16 (“no paid route returns data while bulk is off”) contradicts the required free preview. Replace it with route-specific expected statuses; either implement match or omit it from discovery until usable. Paid mainnet authentication remains a documented TODO, so “one-step switch” is not yet a readiness claim.
- Query enumeration and title-to-ID harvesting are possible during the hold. Bulk copying of public facts is expressly accepted; the abuse problem is compute exhaustion, identity-service extraction and distorted demand metrics. Bulk 404 and robots.txt cannot prevent these.
- Per-IP quotas allow proxy/IPv6 rotation and penalize shared NATs. The Worker rate-limit binding is approximate and location-local, not a strict daily counter; specify coordinated daily accounting and failure behavior. REST/MCP must share the original-client budget, including batched calls. [Cloudflare binding](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/)
- Bound title/body/filter lengths, result counts, pagination, diff spans and CPU; reject before expensive work. Add a global circuit breaker and budget alerts. Static cache misses, random paths and query-string cache busting need canonical keys, path validation and negative caching. CORS does not stop scripted miss-beacon spam.
- Prices exceed the cited settlement fee only before compute, storage, failed attempts, payout fees and support. At $0.002 query, the cited $0.001 fee consumes half gross revenue; the alternative $19/100k plan cannot cover 100k separate $0.001 settlements. Validate batching economics before eventual activation.
- Monetization research states a $0.01 Stripe minimum while checklist proposes a $0.002 purchase: resolve the selected settlement path's actual minimum before L2. Price increases for bulk cannot prevent reconstruction from the promised free dataset.
- “Unique clients/day” cannot be computed from the proposed event fields; UA categories are spoofable. Drop that KPI or define a privacy-reviewed, short-lived pseudonymous identifier. Truncating miss text does not remove personal data; specify redaction, retention, deletion and access controls.
- Measure successful useful calls, empty/match-failure rates, p95 latency, 429/5xx, bytes, cache misses and cost per successful call. Separate tests/bots/retries and count logical MCP calls once. Would-be-paid traffic measures usage, not willingness to pay; require repeat use and user feedback before interpreting it commercially.
- **Exit:** executable off/on route matrix, off-mode zero payment attempts, bulk 404, shared REST/MCP quotas with Retry-After, bounded-input/load tests and fail-closed on-mode tests; discovery matches actual routes. A reproducible weekly metrics query and privacy/retention contract must work before announcement. Keep paid off.

3. **P1 — Separate free-launch readiness from the full hosting migration.**
- A dynamic Worker is needed for server-side preview controls; moving the entire site is not established as necessary now. GitHub restricts sites primarily facilitating commercial transactions/SaaS; future paid plans alone do not prove the present free publication violates that rule. Assess current use and move before a conflicting commercial use. [GitHub limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)
- The 20k claim is correct for Workers Free; Workers Paid allows 100k assets. At the stated 18,365 files, headroom is 1,635 files (~8%). This is a growth constraint on the proposed destination, not a GitHub Pages file-count limit; measure artifact bytes and growth too. [Cloudflare limits](https://developers.cloudflare.com/workers/platform/limits/)
- Keep the free shell/static publication temporarily while introducing the gateway and release archive, or explicitly budget the full cutover. Metrics collection does not itself require migrating the shell. Retained release history can be added without making R2 the only live origin immediately.
- “Bulk static crawling costs nothing” is false: R2 has free egress but metered storage/operations; Worker execution remains relevant. Standard includes 10 GB-month, 1m writes and 10m reads; overage is $0.015/GB-month, $4.50/m writes, $0.36/m reads. The stated 9.2 GB raw archive nearly fills storage allowance before releases. [R2 pricing](https://developers.cloudflare.com/r2/pricing/)
- Add expected/cold-cache/abuse cost estimates including Worker, daily-counter and analytics allowances. Worker Free currently allows 100k requests/day; routing static data through it introduces a shared availability budget. [Worker limits](https://developers.cloudflare.com/workers/platform/limits/)
- Publishing GH Pages before validating R2 creates split releases; a cached current pointer can mix indexes and records unless requests pin a release. Verify manifest counts/checksums, upload completeness and policy version before pointer promotion; retain a tested rollback pointer.
- A 365-day release lock can obstruct source takedowns; raw locks can conflict with stated 72-hour retention. Define source-specific retention and a serving-layer revocation path covering old releases, caches and fallback origins; do not promise physical removal while objects remain locked.
- “Redirect GH Pages” plus continued normal publishing can overwrite the redirect or leave JSON clients consuming HTML. Specify separate fallback artifacts and preserve API/deep-link behavior. Test DNS/TLS, CORS, legal/discovery paths, cache invalidation and origin rollback.
- **Exit:** choose and document the minimum L1 topology; prove one-source backup restore and an end-to-end release promotion/rollback; set operational budgets and alerts. Launch only with approved free legal/privacy/source pages, verified contact delivery, visible freshness/coverage/unknown states, and a correction/takedown runbook. Directory submissions and a paid switch are not free-launch acceptance criteria.
