# Astra review 3 — 2026-11-23

Scope: only the requested reports, profiles, identity/category files, category policy blocks, and two shared adapters. Findings below are static-review risks; source-specific adapters and rendered UI were outside scope.

## Identity

- **Robovac can merge different hardware transitively.** `group()` unions on ANY SKU **or** normalized model name, without checking dock/generation disagreements; A↔B and B↔C therefore collapses A↔C. The report's “grouping is by shared SKU” omits the independent name path (`crawler/adapters/_robovac.py:52`, `crawler/adapters/_robovac.py:65`; `team/reports/2026-11-23-a12-robot-vacuums.md:10`). A reused SKU or stripped suffix can contaminate every claim in the group.
- **The entity mixes robot and sellable system.** Plus/RDS are separate models because their docks differ, while Complete is collapsed and “Set” stays separate despite unknown contents (`research/robot-vacuums/identity.md:17`, `research/robot-vacuums/identity.md:24`; `research/robot-vacuums/spec-profile.yaml:26`). This risks duplicate robot comparisons and assigning one bundle's dock capabilities to another. Anchor the sellable system to verified robot-model + dock-model + hardware revision; represent accessory packs separately. Keep existing IDs stable and attach evidenced mappings when labels arrive; a regulatory/radio ID alone is not sufficient evidence for identical docks.
- **Names are provisional anchors, not global equivalence.** The wildcard cross-market rule is supported only by US sources; the category documents quarantine for different *stated* markets, which does not address unstated-market variants (`research/robot-vacuums/category.yaml:27`). Require explicit equivalence before adding other markets, and preserve suffixes/revisions. Use names for discovery and verified material codes plus component labels for corroboration.
- **Power-bank “model number” is heterogeneous.** Belkin truncates variant SKUs, INIU has a handle fallback, and UGREEN uses a sales item number rather than the PB label model (`research/power-banks/identity.md:10`). Truncation can hide revisions; item numbers can split identical electrical hardware. P41/P41-E1 already collapse when both pages print P41 despite the suffix-preservation rule (`research/power-banks/identity.md:19`, `research/power-banks/identity.md:25`). Prefer issuer + printed label model + revision, retain item/colour/channel codes as typed aliases, and quarantine page/handle disagreements. Do not merge BBA/BPB or editions merely because specifications match.

## Semantics

- **Claim origin is not a comparison method.** Suction is a range facet and headline column despite the profile explicitly declaring cross-brand incomparability (`research/robot-vacuums/spec-profile.yaml:176`, `research/robot-vacuums/spec-profile.yaml:193`). Shared `mfr_in_house_lab` does not establish shared inlet, location, duration, or test protocol. Show “manufacturer-claimed maximum; methods differ” beside the number; do not present higher Pa as better cleaning performance.
- **Runtime/noise conditions remain insufficient.** Quiet/standard/max collapses maker-specific settings; `power_mode()` chooses the first matching keyword even if a cell describes several modes (`crawler/adapters/_robovac.py:215`). Runtime needs vacuum/mop operation and surface; noise needs distance, weighting, and robot-versus-dock operation (`research/robot-vacuums/spec-profile.yaml:481`, `research/robot-vacuums/spec-profile.yaml:667`). Keep native mode and test wording attached to each number; unknown conditions must not constitute a comparable cohort. Suction also lacks an explicit operating-mode condition (`research/robot-vacuums/spec-profile.yaml:183`).
- **Certification detection overstates evidence.** `basis_for()` matches a number anywhere in a disclaimer and then any certifier token, even “not certified by SGS”; “laboratory” alone becomes in-house (`crawler/adapters/_robovac.py:297`). Require affirmative, metric-specific attribution; distinguish manufacturer-reported certification from a checked certificate. The report says current suction claims contain no certifications, so this is a latent parser risk (`team/reports/2026-11-23-a12-robot-vacuums.md:16`).
- **Capacity fields must stay distinct in comparisons.** Class mAh is marketing; cell mAh requires a nominal-voltage basis; pack mAh at 7.4 V is neither a cell-equivalent headline nor 5 V delivered capacity. The profile calls `cap.cell_voltage` “Cell nominal voltage” but includes 7.4 V packs, and still lists Belkin title-only data as a cell-mAh source (`research/power-banks/spec-profile.yaml:163`, `research/power-banks/spec-profile.yaml:199`). Separate pack/cell voltage and remove that stale source guidance. A missing series voltage does not positively prove a generic capacity row is cell capacity (`data/decisions/policies.yaml:264`).
- **Rated output capacity needs an inseparable basis.** `cap.rated_basis` is a separate detail field, not a condition on `cap.rated_mah`; values at different voltages/currents can be detached or compared incorrectly (`research/power-banks/spec-profile.yaml:232`). Store/display value + voltage + current + rating basis together. Do not backfill missing cell mAh with class or rated-output mAh. Wh describes stored energy, not delivered energy under a common load.
- **Do not silently choose one of two Wh figures.** The profile chooses the lower of 74/75.5 Wh and calls it rated energy; that is justified only when the source explicitly labels rated versus typical (`research/power-banks/spec-profile.yaml:213`). The shared `wh()` simply takes the first match, not a labelled role (`crawler/adapters/_powerbank.py:43`). Preserve both typed figures, or leave the scalar unresolved when unlabeled.
- **“Max total output” disguises an all-ports condition.** The 15 W all-port figure versus 45 W single-port figure is not the maximum across every configuration (`team/reports/2026-11-23-a12-power-banks.md:20`). Label it “All-ports simultaneous output,” record which ports participate, and keep unspecified `out.max_output_w` out of total/single-port rankings. Remove Belkin “Wattage” from the total-output source list (`research/power-banks/spec-profile.yaml:274`, `research/power-banks/spec-profile.yaml:293`).
- **The shared total parser does not establish all-port coverage.** It selects the combination with the most separators, treats two ampersand-connected ports as individual outputs, and gives any `Total(...)` label priority 99 (`crawler/adapters/_powerbank.py:177`, `crawler/adapters/_powerbank.py:187`). Thus a subset total can become all-ports total, and `65W+15W (Total)` is summed despite the “as printed” contract. Match explicit participating ports against the physical inventory; keep derived sums marked derived and unproven totals preview-only.

## Trust

- **Allowlists are not narrow enough semantically.** Source/key/type gates cannot distinguish an explicit statement from the parser inferences above. Robovac explicitly trusts keyword classes; power banks trust port tables/totals and share one key list across three stores (`data/decisions/policies.yaml:329`, `data/decisions/policies.yaml:357`, `data/decisions/policies.yaml:382`). Require evidence-form and ambiguity checks per field, in addition to normalized type. Belkin title capacity is an intentional exception that contradicts the report's blanket “no title-derived keys” assertion (`data/decisions/policies.yaml:262`; `team/reports/2026-11-23-a12-power-banks.md:7`).
- **Current enum inference is unacceptable for trusted capability filters.** “laser” becomes structured light; any “camera/vision” becomes RGB; “visual” becomes vSLAM; “dual mops” or any “rotating” becomes dual spinning; “pad” becomes static (`crawler/adapters/_robovac.py:251`, `crawler/adapters/_robovac.py:267`, `crawler/adapters/_robovac.py:282`). Negation is ignored. Examples: “no camera” emits RGB and “single rotating mop” emits dual spinning. Trust only explicit affirmative mechanism phrases; leave generic/ambiguous text as preview. The navigation enum also separates dToF from LiDAR despite describing dToF as LiDAR, so a LiDAR filter needs hierarchy-aware matching (`research/robot-vacuums/spec-profile.yaml:391`).
- **Plausibility bounds should quarantine, not erase or certify.** A 1.5–7.5 kg / 200–450 mm rule is a sanity check, not component identification; an in-range mixed cell can pass and a legitimate outlier can disappear (`crawler/adapters/_robovac.py:350`). Preserve raw rejected cells with reason and locator as unresolved preview evidence, never as normalized robot values. Split robot/dock only with explicit labels; otherwise keep both numeric fields unknown. First-triple parsing cannot establish component ownership (`crawler/adapters/_robovac.py:199`).
- Both policies remain `approval: pending`; accepted/imported counts do not establish approval. Whether pending state gates publication cannot be verified in this scope (`data/decisions/policies.yaml:280`, `data/decisions/policies.yaml:370`; `team/reports/2026-11-23-a12-robot-vacuums.md:51`).

## Top three fixes, ranked

1. **Block false trusted semantics before policy approval.** Narrow enum/certification parsing and require explicit port membership for totals. Exit: fixtures for “no camera,” generic laser/visual, single rotating mop, negated certification, two-port `&`, subset totals, and additive wattage produce no unsupported trusted values; positive explicit examples retain literal evidence; affected claims are replayed and policy fingerprints updated.
2. **Make identity grouping conflict-aware.** Replace unconditional SKU/name union with corroborated system identity; quarantine contradictory robot/dock/revision members and power-bank handle/label disagreements. Exit: a three-page SKU bridge cannot merge incompatible endpoints; Plus/RDS remain distinct; verified colours/Complete packs resolve consistently; P41/E1 ambiguity is reviewable; UGREEN item-to-label mappings preserve existing IDs without automatic equivalence.
3. **Bind numbers to shopper-visible conditions and retain rejected evidence.** Separate capacity bases, rename all-port output, expose native mode/test conditions, and retain mixed robot/dock cells as unresolved preview. Exit: 15 W all-port and 45 W single-port remain visibly distinct; 10K class never fills cell mAh; 5 V ratings retain load; unlabeled dual Wh values stay unresolved; mismatched suction/noise/runtime methods cannot imply comparable performance; every plausibility rejection has an inspectable literal and reason.
